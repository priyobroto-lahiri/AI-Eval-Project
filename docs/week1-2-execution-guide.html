// First — Your 5 Questions, Answered Directly
No Ambiguity. Read This First.
Q1 // Is this for my understanding offline, or do I push these files to my GitHub repo too?
Push everything to GitHub from Day 1. Nothing stays on your laptop only. Every notebook, every script, every diagram goes to GitHub. Here is the rule: if you wrote it, it's public. Your GitHub is your resume — an empty repo tells employers nothing. A repo with 40 commits that shows your thinking process, your mistakes, and your fixes is worth more than a perfect project uploaded on day 120. Think of GitHub as your public work diary, not a submission box.
Q2 // What offline IDE should I use?
VS Code + Jupyter extension. Install VS Code (free, by Microsoft). Then install the "Jupyter" extension inside VS Code. This gives you: a real code editor, Git integration built in, Jupyter notebooks that run inside VS Code, a terminal, and auto-complete. You get everything in one window. Do NOT use PyCharm (too heavy for beginners), do NOT use bare terminal Jupyter (no Git integration). Also install Anaconda — it installs Python, Jupyter, Pandas, NumPy, and Matplotlib all at once so you never have to fight dependency errors.
Q3 // What accounts to open?
4 accounts, in this order: GitHub (your code home), Hugging Face (your live demo home), Anthropic (for API key to call Claude), and LinkedIn (optimized for your new identity). Details with exact steps in the Accounts section below.
Q4 // What tutorials / YouTube videos for Jupyter and Pandas?
Two channels, in this exact order: Start with Corey Schafer's Jupyter Notebook tutorial (1 video, 30 min — the clearest setup walkthrough on YouTube). Then watch Keith Galli's Complete Pandas Tutorial 2024 (1 video, covers everything you need). Both are free on YouTube. Links and exact video names in the Tutorials section below.
Q5 // Is a benchmark table just for my README or does it go in the notebook too?
Both — for different purposes. In your notebook, the benchmark table is generated by your code (a Pandas DataFrame printed as a table). In your README on GitHub, you copy-paste the results as a Markdown table so recruiters can see your results without opening any files. The README version is what gets you hired — most recruiters never open a .ipynb file.

// Step 2 — Day 1 Afternoon
Install Your IDE — Exact Steps
The stack: Anaconda (Python + all data science libraries) + VS Code (editor) + Jupyter extension (notebooks inside VS Code) + Git (version control). Total install time: ~30 minutes.
1
Install Anaconda First
This installs Python, Jupyter, Pandas, NumPy, Matplotlib all at once
~15 min

Go to anaconda.com/download → download the installer for your OS (Windows/Mac/Linux) → run the installer → accept all defaults → check "Add Anaconda to PATH" if asked.

After install, open your terminal (Command Prompt on Windows, Terminal on Mac) and type:

conda --version

If it prints something like conda 24.x.x, the install worked.

Now create a dedicated environment for your eval projects:

# Create environment named "evalenv" with Python 3.11 conda create -n evalenv python=3.11 # Activate it (you'll do this every time you work) conda activate evalenv # Install the core libraries pip install pandas numpy scikit-learn matplotlib jupyter ipykernel anthropic python-dotenv
Why a separate environment? It keeps your project libraries isolated. When you add more libraries in later phases (Ragas, DeepEval, LangChain), they won't conflict with each other. This is professional Python hygiene.
2
Install VS Code + Extensions
Your permanent coding home for all 5 phases
~10 min

Go to code.visualstudio.com → Download → Install.

Open VS Code. Press Ctrl+Shift+X (Extensions panel). Search and install these 4 extensions:

1. "Jupyter" — by Microsoft (run notebooks inside VS Code) 2. "Python" — by Microsoft (Python language support) 3. "GitLens" — by GitKraken (see Git history inline in code) 4. "Prettier" — by Prettier (auto-formats your code cleanly)

Now tell VS Code to use your conda environment: press Ctrl+Shift+P → type "Python: Select Interpreter" → choose the one that says evalenv.

To create a Jupyter notebook in VS Code: press Ctrl+Shift+P → "Create: New Jupyter Notebook" → a .ipynb file opens. Click the kernel selector (top right) → pick evalenv. Now you can run Python cells.

VS Code + Jupyter is better than the browser-based Jupyter for your use case because you have Git integration right there. You can commit and push your notebook to GitHub without switching apps.
3
Install Git and Connect to GitHub
The thing that makes your work public and trackable
~10 min

Download Git from git-scm.com → install with all defaults.

Open terminal and set your identity:

git config --global user.name "Your Full Name" git config --global user.email "your@email.com"

To push code from VS Code to GitHub, you'll use the Source Control panel (the branch icon on the left sidebar). The first time, VS Code will ask for your GitHub login — use the Personal Access Token you created in Step 1, not your password.

The 3 Git commands you'll use every day:

# Stage all changed files git add . # Save a snapshot with a message (write what you did) git commit -m "Add similarity engine notebook - Jaccard method complete" # Push to GitHub git push
Commit rule: Every time you finish a meaningful chunk of work — even if it's just adding 10 lines — commit it. Message format: "[action] [what] — [why/result]". Example: "Add cosine similarity — scores 0.87 on test pair". This builds a compelling commit history that recruiters can read like a story.

How to Write Benchmark Tables — Two Versions

A benchmark table shows your results at a glance. You write one in your Jupyter notebook (using Pandas) and copy a version into your README (using Markdown). Here's both.

Version 1 — In your Jupyter Notebook (Python + Pandas)
// Paste this into a cell in your notebook
import pandas as pd # Build your results table results = { "Method": ["Jaccard", "TF-IDF Cosine", "ROUGE-L", "Semantic (MiniLM)"], "Pair 1 Score": [0.42, 0.71, 0.58, 0.89], "Pair 2 Score": [0.10, 0.33, 0.21, 0.82], "Best Use Case": ["Exact match check", "General similarity", "Summary eval", "Semantic eval"] } df = pd.DataFrame(results) # Display as a styled table in the notebook df.style.highlight_max(subset=["Pair 1 Score", "Pair 2 Score"], color="#d4edda")

Key Finding

Semantic similarity (MiniLM) scored 2x higher than Jaccard on paraphrase pairs — confirming that meaning matters more than word overlap for LLM evaluation.

Failure Case

Jaccard gave 0.04 for "The car failed" vs "The vehicle broke down" — while semantic similarity gave 0.91. This is why semantic similarity is the primary metric.

Markdown table anatomy: The first row is the header. The second row (|---|---|) is the separator — required. Every row after is data. Columns are separated by | pipes. You can align text with :--- (left), :---: (center), or ---: (right) in the separator row. That's all there is to it.

// Bonus — Complete Starter Code for Project 0.2
The Batch Runner — Ready to Paste and Run

Create a file called .env in your project folder. Put your API key there. Never push this file to GitHub — add .env to your .gitignore.

// .env file (do NOT push to GitHub)
ANTHROPIC_API_KEY=sk-ant-your-key-here
// .gitignore file (create this, push it — it tells Git to ignore .env)
.env __pycache__/ *.pyc .DS_Store results/
// batch_runner.ipynb — paste each block into a separate cell
# Cell 1 — Imports import pandas as pd import anthropic import time import os from dotenv import load_dotenv load_dotenv() # reads your .env file client = anthropic.Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY")) print("✅ Client ready")
# Cell 2 — Load prompts from CSV # Create prompts.csv first with columns: id, category, prompt df_prompts = pd.read_csv("prompts.csv") print(f"Loaded {len(df_prompts)} prompts") df_prompts.head()
# Cell 3 — Run the batch results = [] for _, row in df_prompts.iterrows(): start = time.time() response = client.messages.create( model="claude-haiku-4-5-20251001", # cheapest model max_tokens=500, messages=[{"role": "user", "content": row["prompt"]}] ) latency_ms = round((time.time() - start) * 1000) results.append({ "id": row["id"], "category": row["category"], "prompt": row["prompt"], "response": response.content[0].text, "input_tokens": response.usage.input_tokens, "output_tokens": response.usage.output_tokens, "latency_ms": latency_ms }) print(f"✅ Done: {row['id']} ({latency_ms}ms)") df_results = pd.DataFrame(results) df_results
# Cell 4 — Summary table summary = df_results.groupby("category").agg( avg_latency_ms = ("latency_ms", "mean"), total_input_tok = ("input_tokens", "sum"), total_output_tok= ("output_tokens", "sum"), count = ("id", "count") ).round(1) # Estimated cost (Haiku pricing: ~$0.00025/1K input, $0.00125/1K output) total_cost = (df_results["input_tokens"].sum() * 0.00025 / 1000 + df_results["output_tokens"].sum() * 0.00125 / 1000) print(f"💰 Total estimated cost: ${total_cost:.4f}") print(f"⚡ Avg latency: {df_results['latency_ms'].mean():.0f}ms") summary
# Cell 5 — Save results df_results.to_csv("results/batch_results.csv", index=False) print("✅ Saved to results/batch_results.csv") print("📌 Push to GitHub: git add . && git commit -m 'Add batch runner results' && git push")
Exit criteria for Project 0.2: You can open a terminal, activate evalenv, run this notebook end to end against 10 prompts, and see a clean results DataFrame with latency and token counts. Then push everything to GitHub. That's Week 2 done.
